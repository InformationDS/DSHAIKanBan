# AIKanBan for DSH

**English** | [中文](README.md)

A Trello-style project kanban plugin: tasks are not assigned to *people*, but to *conversations* (DSH sessions). One task can be carried forward by multiple conversations — in serial relay or in parallel exploration — and cross-session handoff is carried by user-confirmed, versioned memory.

All AIKanBan documents, source code and artifacts live under [`AIKanBan/`](AIKanBan/).

## Core concepts

| Kanban concept | In this plugin |
| --- | --- |
| Members (who does the work) | DSH conversations (sessions); cards carry a "conversation work log", and every conversation has its own detail page |
| Cards (tasks) | Work items: title, goal, progress, next step, blocked reason — 5 statuses |
| Columns | Status flow: Not started / In progress / Blocked / Done / Canceled |
| Handoff document | Task memory (6 sections) + project memory (5 sections), versioned, effective only after user confirmation |
| Workflow rules | Status is ultimately decided by the user; the AI only proposes — effective after diff review |

## Product form

A full-width **"📋 Board" tab** next to "Chat" in the DSH session header (the `conversation.view` slot): a 5-column status board, drag-and-drop card transitions, work item detail (conversation timeline), conversation detail page, proposal review queue, project memory page, and handoff context generation.

Since v4: the board can generate task/project memory proposals directly via the "✨" buttons — the current session's agent drafts them in chat and submits them for review. Clicking "＋ New conversation" inside a work item automatically injects the latest handoff context as the new session's first message (with a degraded-mode notice plus a manual "Inject context" button on the conversation row as fallback).

## Core principles (user confirmation first)

1. Anything the AI generates is always a proposal: the agent drafts → the user reviews the diff on the board, edits, confirms or discards → only then does it become official memory.
2. Unconfirmed content never enters the handoff context.
3. At most one active proposal per scope (task = a single work item; project = global); once the base version is superseded, the old proposal expires automatically.
4. Data is persisted to `.dsh-kanban.json` in the workspace root (single file, gitignored, machine-local) and reused across sessions and restarts.

## Usage

1. In any DSH session (workspace = this repository), ask the agent to rebuild the plugin following [`AIKanBan/REBUILD.md`](AIKanBan/REBUILD.md), then approve it.
2. A "📋 Board" tab appears in the session header; ask the agent in chat to draft memory proposals and confirm them on the board.
3. To continue the same work item in a new session: have the agent read [`AIKanBan/HANDOFF.md`](AIKanBan/HANDOFF.md) or call `kanban_get_handoff_context` directly — the new conversation then shows up on the timeline automatically. Since v4, clicking "＋ New conversation" inside a work item binds and injects the handoff context automatically, with no manual fetching.
