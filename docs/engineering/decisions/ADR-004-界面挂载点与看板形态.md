# ADR-004：界面挂载点与看板形态

| 信息 | 内容 |
| --- | --- |
| 日期 | 2026-10-14 |
| 状态 | 提议 |
| 影响功能 | F01、F02、F04、F15、F16、F17、F19、F20 |
| 被替代关系 | 无 |

## 要解决的问题

AIKanBan 需要落地产品总览「信息架构」中的五个区域：项目看板、任务详情、项目对话列表、对话任务侧栏、项目总览与成果（含集中待确认）。这些区域必须挂在 DSH 客户端已有的 Slot 座位上，不能另建一套窗口或替换官方界面。需要确定：看板作为什么形态存在、每个区域落在哪个 Slot、哪些 Slot 明确不可用。

本决定只定界面挂载结构，不改变任何业务规则；布局、密度、断点仍按各 PRD 的「实施边界」由设计决定。

## 可核对的宿主事实

对当前活动的 Client 半做只读 Slot 拓扑检查（`cordis_inspect_query`，platform `client`，provider `Slots`，method `listSubTree`，root `root`），得到以下实际存在的座位：

| Slot | kind | scope | 说明与替换风险 |
| --- | --- | --- | --- |
| `main` | keyed | root | 「Central panel selected by sidebar entry id」。keyDomain 为 **open**：`any string the owner dispatches (no compile-time key set)`，已占用：`conversation` |
| `sidebar.panellist` | list | root | 全局面板图标；注册项需 `id`，可选 `order`/`label` |
| `sidebar.workspaces` | single | root | 工作区/会话浏览区，替换风险 `shadows-shipped-ui` |
| `sidebar.workspaces.session.menu.item` | list | root | 单个会话「…」菜单的行 |
| `sidebar.session.row.leading` | list | root | 会话行前 16px 装饰格 |
| `sidebar.session.row.hover` | list | root | 会话行悬浮卡中的一段 |
| `conversation.session.header.actions` | list | session | 会话标题旁动作 |
| `conversation.session.header.utilities` | list | session | 会话标题右侧工具区 |
| `sidebar.right.pane.tab` | keyed | session | 右侧栏「一个 tab 的 body」，按 `tab.kind` 派发；keyDomain 为 open |
| `sidebar.right.pane.tab.title` | keyed | session | 同一 tab 的标题（chip / 浮动面板 header） |
| `shell.overlay` | list | root | 全框浮动层，`click-through until your entry opts into pointer events` |
| `settings.section` / `settings.general.item` | list | root | 设置页 / 单条偏好行 |
| `root` | single | root | 已被 ui-layout 的 AppFrame 占用；**明确禁止注册**（见下） |

客户端 Slot 层提供的注册入口是 `ctx.slots.register(options, component)`（另见 `registerFactory`、`inject`），scope 为 `root` / `session-maybe` / `session`。

### 关键否定事实

**`conversation.view` 在当前 Slot 目录中不存在。** 已封存的旧实现曾把自己的看板挂在该键上；当前活动 Client 半的座位清单里没有这个键，因此该路径在当前 DSH 版本上不可用，新实现不得沿用。若未来 DSH 重新提供等价座位，本 ADR 需被替代。

**`root` 不可注册。** 其目录说明为：单值槽，第二个条目不是"并排"而是"遮蔽"官方框架，且动态注册项优先级低于官方项从而成为胜者，结果是整页只剩自己的组件、官方框架声明的所有座位消失。需要全应用范围的浮动界面时注册到 `shell.overlay`。

## 可选方案

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 注册 `main` 新 key（如 `kanban`）+ `sidebar.panellist` 图标 | 看板成为与「对话」并列的主面板；切换由面板 id 驱动 | 采用 |
| B. 复用旧实现的 `conversation.view` | 在看板作为会话视图的一个页签 | **不可用**：该座位在当前 DSH 不存在 |
| C. 替换 `sidebar.workspaces` 嵌入看板 | 把看板做进左侧栏浏览区 | 拒绝：单值槽且 `shadows-shipped-ui`，会遮蔽官方会话浏览 |
| D. 注册 `root` 自绘整页 | 完全接管界面 | 拒绝：会遮蔽官方框架并使其声明座位消失 |
| E. 只做 `shell.overlay` 浮层 | 看板作为覆盖全应用的浮层 | 拒绝：整块工作区不适合浮层，且与「不被多层管理页面遮住主要动作」冲突 |

## 采用方案

**方案 A**，配合会话范围座位：

| 产品区域 | 落地座位 | scope |
| --- | --- | --- |
| 项目看板（主工作区） | `main`（新 key） | root |
| 看板入口图标 | `sidebar.panellist` | root |
| 任务详情 | `main` 内视图（宽窗口可并排），沿用同一选中任务身份；不使用 `rightbar` 作为唯一载体 | root |
| 项目对话列表 | `main` 内视图（与看板同面板切换） | root |
| 对话任务侧栏（归属/正式概况/实际背景版本/整理与返回） | `sidebar.right.pane.tab` + `sidebar.right.pane.tab.title` | session |
| 会话级快捷动作（关联任务、形成任务记录） | `conversation.session.header.actions` | session |
| 会话列表行标记（归属/待整理） | `sidebar.session.row.leading`（16px 装饰）+ `sidebar.workspaces.session.menu.item` | root |
| 集中待确认与一次事件提醒 | `main` 内视图 + `shell.overlay`（仅事件提醒，须自行 opt-in 指针事件与去重持久化） | root |
| 看板偏好（语言、时间等） | `settings.general.item`；不新增独立设置页，除非确有整页需要 | root |

**明确不使用**：`root`（遮蔽风险）、`sidebar.workspaces`（单值遮蔽）、`sidebar.brand.*`、`conversation.view`（不存在）。

**面板切换**：客户端 `ctx.layout.selectPanel(panelId | null)` 是面板导航入口；`sidebar.panellist` 注册项与 `main` key 共用同一 id。

## 影响与代价

- 正面：不遮蔽任何官方界面；与「不重新实现桌面统一主题/字体设置」「不抢占宿主全局快捷键」的既有约束一致；每个区域都有对应座位，无需自建窗口。
- 代价与限制：
  1. 会话行可用信息面很窄（`leading` 只有 16px、悬浮卡只有一段、菜单只能加行），**「归属/待确认/新内容」的完整表达必须落在看板自身面板内**，会话行只做轻量标记。这与 F04「列表展示真实标题、运行状态和归属」需要重新对表：该 PRD 描述的列表应理解为看板内的项目对话列表，而非官方会话侧栏。
  2. `sidebar.right.pane.tab` 是 `session` scope 的 keyed 槽，keyDomain 为 open，但需要与右侧栏现有的 tab 类型派发机制对齐；具体注册方式须在实现时确认（列入未验证项）。
  3. `shell.overlay` 不接管指针事件，事件提醒需要自行处理点击穿透与「只提醒一次、重启不重复」的去重持久化；宿主没有独立的通知服务。
  4. 看板成为 main 面板意味着用户在「对话」与「看板」之间切换主面板，而不是常驻并排。窄窗口与宽窗口的具体布局由 F19/F02 决定，本 ADR 不锁定。

## 验证证据

- 只读 Slot 拓扑检查（`Slots.listSubTree`，root `root`）输出的座位清单与其 `kind`/`scope`/`replaceRisk`/注册字段，构成本 ADR「宿主事实」一节的直接依据。
- `main` 的 keyDomain 文字明确为开放字符串集合、已占用 `conversation`，是方案 A 可行的直接依据。
- `root` 的「DO NOT register here」说明与 `conversation.view` 的缺失，是方案 B/D 被否的直接依据。

## 尚未验证

- `sidebar.right.pane.tab` 的注册细则（与现有 tab 类型派发、标题 hook 的配合）。
- `shell.overlay` 中自绘事件提醒的指针事件 opt-in 方式。
