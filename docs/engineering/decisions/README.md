# 技术决策记录

本目录按 `ADR-001-主题.md` 的形式记录重要技术决策：文件名由稳定编号加主题组成，编号一经分配不再更改、不再分配给别的决定。需求拆分与功能 PRD 描述产品行为，**不以需求拆分替代工程决定**；工程上为什么这样选，记录在本目录。

## 每份记录的内容

每份记录至少包含：日期、状态、要解决的问题、可选方案、采用方案与理由、影响功能、约束/代价、验证证据、被替代关系。未验证的内容必须标为未验证，**不得写为已验证**。

## 状态约定

| 状态 | 含义 |
| --- | --- |
| 提议 | 已记录并说明理由，但尚无实现、探针或真实运行证据 |
| 采用 | 有可核对的验证证据，且当前有效 |
| 替代 | 已被后续记录取代，保留编号并注明替代关系 |

只有实现、探针或真实运行给出证据后才能把 `提议` 改为 `采用`；被替代的记录不删除、不重复使用编号。证据写实际命令、输出或观察结果，不写预期结果。

## 应用时机

- S0 开发准备及后续必要的架构决定（交付形态、宿主能力边界、存储与并发模型、界面挂载与数据通道等）在做出选择时记录为 ADR，而不是散落在任务说明或提交信息里。
- 同一决定被推翻时新增记录并注明替代关系，不改写旧记录的结论。
- 日常实现进度**不写在本目录**，只维护在[交付状态](../../delivery/status.md)；本目录只回答「为什么这样决定」。

## 边界

技术决定不得改变成对保存、固定归属、历史隔离、人工修正等产品语义。需要改变用户可见行为时，先更新有效 PRD 与决策来源，再记录工程决定；不得以「实现方便」为由在 ADR 中改动产品规则。
