# 公共规则：关键结论的当前适用性

来源：FR-06、13、17、20—22、24—25、31，AT-64—71、106。适用性规则需作为保存/读取合同从最早的正式内容功能预留，F09 实现具体修正操作与跨来源核验。

## APP-01 版本与适用性分开

最新保存正文不代表每个结论当前有效。只对影响工作的决策、约束、验证结论及相关片段标注，不逐句审批。某片段失效不废弃同记录其他有效成果。

## APP-02 四种结论状态

| 状态 | 工作使用 |
| --- | --- |
| 当前适用 | 在确认范围作为依据，验证不扩展到未验证方案 |
| 已被替代 | 用替代结论，旧结论仅作带说明的阶段背景 |
| 已否定 | 不作当前事实，附修正说明与依据 |
| 待确认结论 | 正式保存为未决问题，不能作确定依据 |

“待确认结论”不是草稿未确认，也不是“概况待核对”；它可以在内容一致时成对正式保存。

## APP-03 修正须明确且有范围

缩短摘要、删除摘要一句、未选进某次汇总不自动否定来源。否定/替代需要明确含义及用户确认，指明受影响关键片段、适用范围、修正来源和替代内容。

范围可以是当前任务或项目共同规则；本任务否定 A 不因相同文本撤销其他任务的 A。后续阶段进展替代早期状态不必判早期记录当时错误。

## APP-04 修正与汇总同次生效

用户在概况/总览改结论时，核对受影响来源片段与范围，在同次预览确认后生效；不能仅保存纠正文案仍无标识返回被否定片段。保留正文和历史，附适用性视图，不改原始聊天。

AI 可提出匹配、替代、核对建议，不能自行否定或判冲突胜者。匹配/影响不确定明确需核对，由用户通过 AI 建议或手动路径处理；不继续作为确定事实。

## APP-05 修正贯穿所有读出

同范围引用的记录、概况、总览、搜索命中、AI 生成材料必须带已确认修正。项目成果未重生成也不能继续以已失效引用作为当前事实；不能等待成果重生成才保护读取。

当前工作/生成默认返回适用内容、必要修正和验证边界；被否定/替代原句不混入确定事实。追溯可展示原文但同时显示当前状态、范围、修正；未决结论作为问题。

## APP-06 验证边界独立

“A 已验证”不能证明后来采用 B 已验证。记录说明生成、修改、测试通过/未通过/未验证与关键范围，不把计划、候选、未执行测试变成完成或成功。阶段成果可保留，但适用范围准确。

## APP-07 恢复与再次整理

重启、改写记录、恢复历史正文不清除已确认修正。重新采用旧结论须明确确认其适用性。人工删除噪音与纠正须在再次整理中遵守，实质新变化可提出新建议，不能重复恢复旧噪音。

## APP-08 已读内容与后续同步

已提供给对话的旧内容无法宣称撤回。下次明确发送/按需读取/查证/整理携带必要净修正，不自动唤醒闲置对话，不灌入全部纠正历史。同步检测除正文版本还包括有效修正标识；默认背景保留关键约束、风险与必要短提示。
