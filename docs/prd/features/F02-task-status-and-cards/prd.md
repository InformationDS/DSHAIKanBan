## 1. 目标与范围

用户用看板管理任务推进状态，能从卡片看出可信整体进展和需处理事项。
状态是用户管理决定，不能由 AI 本轮结束或记录保存代替。
包含四列看板、已取消折叠、拖拽/菜单状态调整、阻塞原因、顺序、撤销及详情骨架。
F03 提供概况；F04 提供对话；F13/F14 提供项目成果，本功能消费其实际状态。
S1 不展示假造的对话、记录或成果数据，也不把尚未实现的按钮标成可用。

## 3. 用户流程与界面职责

1. 默认展示未开始、进行中、已阻塞、已完成四列。
2. 已取消任务默认收起，可展开查看；已完成任务继续可见。
3. 拖动卡片或使用菜单选择状态。
4. 进入已阻塞且尚无有效原因时，填写原因后确认；取消保持原列。
5. 成功保存后移动卡片，展示可撤销普通流转的反馈。
6. 点击卡片打开详情，返回后保留筛选、定位与项目。
7. 完成任务后显示成果提示；生成成果是另一个动作。

详情通常在看板旁打开，窄窗口可全页，布局不改变行为。
标题、目标、状态、概况和后续功能入口有清楚职责，不重复存储。
全文、来源和历史按需展开，不把全部记录铺在卡片上。

## 4. 功能规则

### F02-R01：状态集合和控制权

状态为未开始、进行中、已阻塞、已完成、已取消。
创建或打开对话、AI 响应结束、任务记录确认、项目成果保存不改状态。
仅用户拖动、菜单或明确指定管理变化生效；聊天意图由 F20 接入。
归档是可见性，不增加第六个任务状态。

### F02-R02：状态流转和阻塞

拖拽与菜单等效；键盘能使用菜单完成状态操作。
进入已阻塞原因必填，原因无效不改变正式状态。
取消输入保持原状态、原列和原原因，不留下已阻塞假象。
从阻塞恢复后解除当前阻塞提示，旧原因保留活动历史。
列内新建阻塞任务同样须先获得有效原因。

### F02-R03：完成、取消和重新打开

完成不强制所有对话停止或记录齐全；仍在运行和未记录工作分别提示。
不自动生成项目记录、不自动归档、不偷偷停止 AI。
已完成或已取消可重新打开，保留正式记录与历史。
已有项目成果时注明前一次完成范围，由 F14 提供来源变化信息。
任务状态和成果状态分别呈现，成果待更新不代表任务未完成。

### F02-R04：顺序与撤销

手动排序模式下同列拖动调整顺序，并可靠保存。
普通状态流转提供撤销，恢复本次操作前的状态和适用字段。
后续已发生新修改时，撤销不能覆盖新修改；提示无法直接撤销并展示当前值。
保存失败保留正式原状态与顺序，不把乐观呈现作为成功结果。

### F02-R05：卡片内容来源

卡片显示标题和一行当前正式概况整体进展；暂无概况时使用任务目标。
不得使用概况草稿或最后一条对话记录替代整体进展。
正式概况不可核对时显示说明，可查看已有记录，不使用未确认摘要兜底。
阻塞原因有文字，状态与风险不只靠颜色。

### F02-R06：行动提示

对话运行、等待用户处理、待确认记录、背景准备失败均按实际结果呈现。
同类提示汇总；多条对话运行时显示数量，点击可选择目标。
存在运行对话、未记录工作或草稿不禁用新建对话。
已完成任务分别显示“待生成项目记录”、已有成果或“项目记录待更新”。
待生成提示不计入待确认草稿数量，历史版本数量不等于待处理数量。

### F02-R07：详情职责与字段一致性

详情展示当前目标、手动状态、正式概况及后续对话/记录/成果入口。
改进展或下一步进入 F03 概况编辑，不再建立第二份进展表单。
审核期间当前字段变化独立可见，其他内容确认不覆盖字段。
更多操作承载取消、归档和删除；永久删除语义交给 F17。

## 5. 异常、取消与恢复

| 场景 | 用户可见结果与恢复 |
| --- | --- |
| 阻塞原因取消/空白 | 原状态原列保持，原因输入保留或明确取消 |
| 流转保存失败 | 正式原状态，显示重试，不显示已完成或已阻塞成功 |
| 连续拖动或重复菜单提交 | 同次操作仅一个结果；后续明确操作按当前状态执行 |
| 撤销时已有新修改 | 说明竞争变化，显示当前值，不覆盖后续结果 |
| 完成时仍有 AI 工作 | 只提示运行及缺失，工作继续，不自动停止 |
| 概况读取失败 | 不清概况，不以草稿补齐，提供重试和记录查看 |
| AI 不可用 | 状态、详情与顺序仍可本地操作 |
| 重启/操作结果未知 | 核对已保存状态和顺序，不重放拖拽或猜测任务完成 |

## 6. 验收条件

所有场景初始为待执行；联合场景必须待关联功能完成后验收。

| 来源 / 类型 | 可执行步骤 | 预期结果 |
| --- | --- | --- |
| AT-03 / 本功能 | 从进行中拖入阻塞，取消，再填写原因确认 | 取消仍进行中；确认后才阻塞，原因可见 |
| AT-03 / 本功能 | 对流转注入保存失败，核对原状态后重试；成功后撤销 | 无半改变；撤销准确；已有后续修改时不覆盖 |
| AT-05 / 联合 F03/F06 | 无概况、有正式概况、有不同内容草稿分别查看卡片 | 目标或正式整体进展正确，草稿和末条记录不冒充概况 |
| AT-04 / 联合 F04/F06/F13 | AI 结束、确认任务记录、保存成果分别检查任务及其他对话 | 三个事件均不改任务状态，不停止其他对话 |
| AT-38 / 联合 F13 | 用户完成任务后等待，再主动生成项目记录 | 完成与生成分别生效，未点击生成无成果草稿 |
| AT-39 / 联合 F04/F13 | 运行对话且有未记录工作时标记完成 | 允许完成，运行和缺失提示真实，无强制停止或补齐 |
| AT-41 / 联合 F14 | 已有项目成果的完成任务重开 | 任务状态改变，前次成果保留并有范围提示 |
| AT-29 / 联合 F06/F08 | 记录审核中改状态，再确认记录 | 状态保持当前用户值，不被记录草稿覆盖 |
| AT-109 | 仅用键盘切状态，展开取消列，返回详情 | 可完成操作，取消默认折叠，定位保留 |

## 7. 实施边界与交接

允许调整卡片密度、详情侧栏/全页和提示排列。
禁止用 AI 运行状态驱动任务状态，禁止完成自动生成成果。
改动范围为任务看板、状态服务、顺序和详情呈现；对话与成果仅接入真实数据。
实现前创建 implementation.md，列清所有状态入口和竞争撤销条件。
验收时创建 verification.md，记录状态失败、键盘等效和卡片来源证据。
进度与验收状态见 [交付状态](../../../delivery/status.md)，不在本 PRD 内维护。
