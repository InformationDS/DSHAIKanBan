# F07：编辑记录后核对汇总

| 属性 | 内容 |
| --- | --- |
| 功能编号 | F07 |
| 优先级 / 阶段 | P0 / S3 |
| 原始来源 | FR-16、FR-17、FR-18、FR-29；UX-04、09、14 |
| 前置依赖 | F06；同次整理对话可接收针对已编辑候选的更新建议要求 |
| 验收来源 | AT-23、27、49、81—85、98—99；项目核对联合 AT-90 |

## 1. 目标与范围

用户编辑或拒绝记录候选后，核对与它一起保存的概况，使两份内容一致且人工编辑不丢失。
本功能扩展 F06 正常一次确认路径，包含分区选择、编辑保留、AI 更新建议、手动核对与保存门槛。
任务记录配任务概况；F13 引入项目记录配项目总览时复用相同规则。
独立编辑正式概况/总览由 F03 负责，明确否定/替代及范围由 F09 负责，正式记录编辑入口由 F10 负责。
本功能不要求用户为了保存未决问题先裁定所有方案，不引入每次输入自动调用 AI。

## 2. 必读规则与依赖

- [确认与版本](../../common/confirmation-and-versions.md)：SAVE-01—08、SAVE-10，一致性核对、一次确认及人工编辑。
- [结论适用性](../../common/conclusion-applicability.md)：APP-02—04、APP-06、APP-07，未决与核对、来源修正及验证边界。
- [保存与恢复](../../common/persistence-and-recovery.md)：REC-01—07，草稿保留与结果未知处理。
- [上下文规则](../../common/context-rules.md)：CTX-02、CTX-03、CTX-08、CTX-09，建议只取必要当前材料并复用整理载体。
- F06 提供成对候选、AI 原稿、正式基线、来源与同次确认身份。
- F08 提供基线变化时重新核对；核对完成仅对用户实际看到的记录、汇总和来源状态有效。
- F13 复用本功能为项目成果核对总览；不要求 S3 提前实现项目成果入口。

## 3. 用户流程与界面职责

1. 打开成对预览，默认突出增加、修改、删除，未变化部分折叠；可展开完整正文与当前正式内容。
2. 用户直接编辑记录，或对分区选择“保留原文”；本条人工结果保留，相关汇总标记待核对。
3. 页面明确显示“记录已修改，概况待核对”；项目配对显示“总览待核对”。
4. 提供“更新概况建议”和“我来手动核对”；项目按钮为“更新总览建议”。
5. AI 路径生成相关差异；用户接受或调整后完成核对，不能仅因请求返回成功解除待核对。
6. 手动路径允许直接编辑概况后“核对完成”，或确认“概况无需修改”；无需理由、无需 AI。
7. 一致性核对完成后执行一次成对确认，没有第二次概况/总览确认弹窗。
8. 离开再返回恢复已保存草稿、人工编辑、分区选择和核对状态。

标签各有明确对象：“待确认结论”对应未决内容，“概况待核对/总览待核对”对应保存一致性门槛。
记录与汇总均为空的候选展示明确删除，不将清空误判为无需更新。

## 4. 功能规则

### F07-R01：预览与分区操作

当前正式正文、AI 原稿和用户结果可辨别，差异中的删除可见，不仅展示一份新稿。
拒绝某分区候选表示保留该区原正式内容；主动清空才表示删除候选内容。
还原 AI 原稿前说明会影响当前人工编辑，不能无提示抹去用户结果。
用户可查看未变化部分及来源，页面折叠不改变保存内容。

### F07-R02：触发一致性核对

编辑、分区拒绝或选择改变记录含义/事实时，相关汇总候选变为待核对。
只改排版且含义不变无需核对；无法确定影响时提示待核对，由用户选择 AI 或手动路径处理。
不得保留被拒绝候选作为汇总的确定结论；拒绝一份候选也不机械删除其他已确认来源支持的相同事实。
记录核对完成后再次实质修改，重新进入待核对；记录与汇总当前基线变动按 F08 处理。

### F07-R03：人工编辑保留

记录与概况两侧人工编辑分别保留；AI 更新建议不直接写入用户稿或正式内容。
建议与人工结果有差异时展示旧人工值、建议及涉及来源，让用户接受、保留或进一步编辑。
同一任务其他对话的有效贡献仍保留，不能为重新核对本条记录删除无关成果。
保存前不追加自动重写、压缩或第二次未经用户查看的 AI 输出。

### F07-R04：AI 更新建议

只有用户明确点击才请求；输入使用编辑后的记录、当前汇总基线、人工修正和必要当前正式来源。
任务更新在本次来源工作对话发送可见整理要求；项目更新在本次系统项目整理对话执行。
不新建另一条任务工作对话，不把重新核对解释为继续开发或执行测试。
独立手动总览编辑需要 AI 核对时由系统创建一次必要整理对话，不继承工作对话全部上下文。
成功返回仍为建议，用户查看并接受相关结果后才解除一致性待核对。
请求失败或中断不能把旧汇总标记为已同步；允许在原草稿重试或切手动路径。

### F07-R05：手动核对

允许用户修正相关汇总后“核对完成”，也允许确认“概况无需修改/总览无需修改”。
手动核对不调用 AI，不要求填理由，不以模型/账号可用作为前置条件。
提示本次待核对的是哪些候选变化及其相关汇总；“核对完成”表示用户已检查这组成对内容。
只删除重复描述而事实不变时可以手动确认汇总无需改变。
手动核对不能自动否定所有来源；明确改变关键结论适用性时进入 F09 的范围与来源确认。

### F07-R06：保存门槛

一致性待核对时点击确认引导处理，不保存正式结果；草稿仍可本地保存。
方案尚未确定、验证结论存在分歧等内容可保留“待确认结论”，不因它未裁定阻止成对保存。
例：两稿都说明“登录方案未定”可保存；记录改为“登录尚未验证”而概况仍说“验证通过”不可保存。
核对完成后使用 F06/SAVE 的一次正式确认；只为真正变化对象生成版本。
点击核对完成并不等于正式确认，正式内容在成对保存成功之前保持原值。

### F07-R07：用户直接字段与汇总

审核期间展示当前任务标题、目标和状态；记录确认不得覆盖这些字段或自动完成任务。
用户可通过 F03 直接编辑概况/总览，无须先编辑来源记录；不回写原始聊天。
AI 想改变已确认人工修正时明确提出差异并由用户决定，不按新生成稿自行覆盖。

## 5. 异常、取消与恢复

- 更新建议失败：两边人工结果和选择保留，继续待核对；显示重试与手动核对入口。
- AI 不可用：仅 AI 建议动作提示原因；手动核对、草稿保存与成对正式确认仍可用。
- 快速连续点击建议：核对同一次执行状态，不盲目重复派发；结果未知先核对真实执行。
- 离开或重启：恢复已保存草稿；未可靠保存的状态需明确提示，不把缺失当已核对。
- 取消建议：保留已输入与候选，一致性待核对不因取消解除；可手动继续。
- 放弃整组成对草稿：正式内容不变，其他草稿独立，处理位置和新内容提示遵守 F06。
- 来源或基线更新：保留人工编辑，按 F08 重核对受影响对象，不能用先前核对结果保存。
- 保存失败：沿用此前正式成对内容，保留编辑和已做选择；仅在基线仍有效时重用核对结果。
- 项目整理源范围变化或任务重开：由 F13/F14 说明具体影响，不能泛称未决结论并直接禁存。

## 7. 实施边界与交接

允许选择差异视图布局和核对提示形式，不能合并两种“待”状态、减少人工保护或增加双重正式确认。
不以可靠性为由强制消除全部方案分歧；内容未决与一致性核对必须分开存储和表达。
F06 的正常未编辑路径必须保持查看后一次确认；本功能不会让所有整理都先执行额外 AI 核对。
OQ-01 的运行中整理策略未定义；本功能只定义已产生候选的编辑和核对，不补队列策略。
实现前创建 implementation.md，验收时创建 verification.md；进度不在本 PRD 内维护。
允许修改成对预览、编辑草稿、建议请求及核对门槛，不重写来源聊天或改任务状态。
