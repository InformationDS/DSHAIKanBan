# F08：并行记录与竞争汇总核对

| 属性 | 内容 |

| 功能编号 | F08 |
| 优先级 / 阶段 | P0 / S3 |

## 1. 目标与范围

同任务多条工作对话独立产生记录草稿，用户先后确认时保留每条贡献和编辑，并看到基于最新概况的实际变化。
同一更新从多窗口或多入口处理，只形成一个正式结果；不同更新竞争汇总时只核对受影响内容。
本功能扩展完整并发交互，不把原子保存和重复确认保护推迟到此阶段：F06 和公共规则从首次实现已保证这些底线。
项目记录竞争总览在 F13 加入后复用本机制；任务重开和完成边界由 F14 提供。
不包含“停止全部”批量控制、跨项目并发合并或运行中整理队列。

## 3. 用户流程与界面职责

1. 同任务 A、B 对话分别点击形成记录，看到两个独立进度与草稿。
2. 用户编辑 B，先确认 A；A 的记录和概况一致生效，B 编辑继续保留。
3. 用户返回 B，界面指出“任务概况已更新”，显示最新正式概况及受影响差异。
4. 保留 B 的独立记录事实，只核对 B 提出的概况变化；如 B 记录自身也变化则单独说明。
5. 通过 AI 建议或手动核对完成新的成对预览，再由用户一次确认。
6. 冲突来源清楚，用户可裁定，也可让两份正式材料保留“待确认结论”。
7. 已由另一窗口完成相同确认时，本入口显示已处理及当前实际结果，不制造第二份历史版本。

反馈须说明变的是“本条记录”“任务概况”“任务目标”“项目总览”或“成果来源”，不能只用泛化过期标签。
对话运行、草稿是否待确认与任务看板状态分别显示；停止一条不停止其他，确认不自动停止工作。

## 4. 功能规则

### F08-R01：独立活动范围

同一对话最多一份活动任务记录草稿，但同任务不同对话可各自整理并确认，不设全任务草稿锁。
每个任务最多一份活动项目成果草稿，不阻挡其他任务成果整理。
手动概况/总览编辑草稿独立保留；重新整理不能覆盖其他记录的活动人工结果。
工作尚未结束或草稿尚未确认不作为其他对话默认事实，只可提示有并行工作尚未记录。

### F08-R02：确认前核对基线

核对本条正式记录、相关汇总、适用修正及任务/来源范围是否与用户看到的基线一致。
本条正式记录被另一处编辑时，旧记录候选需重新核对；保留编辑，不直接覆盖新正式内容。
仅其他对话确认导致概况更新时，不让本条独立记录事实整体作废；刷新相关概况候选。
项目总览仅被其他任务成果更新时，不废弃本任务成果草稿，只核对受影响总览。
核对有效性必须包括影响当前事实的修正，不仅比较正文版本号。

### F08-R03：刷新后的汇总内容

以最新正式概况/总览为基线，纳入本次独立候选与其他已确认有效贡献。
人工修正保护，存在差异时展示来源和建议，不按最后确认者、最后生成者或时间自动裁定。
有实质新变化时展示刷新后增删改，用户核对后重新确认；不能后台重算并自动保存未看过的结果。
更新建议只影响相关汇总，任务状态、标题、目标不由记录确认顺带覆盖。
候选事实相同可合并表达，不能因合并丢失必要来源、风险或验证范围。

### F08-R04：冲突与不确定性

A/B 矛盾方案或验证结果明确各自来源，允许用户裁定或保留为未决问题。
不能要求为了保存独立记录先消除全部讨论分歧；只要两份材料一致表达未定即可正式保存。
来源缺失或无法判定时说明具体影响，不猜哪方正确；一致性尚未核对时维持保存门槛。
对某结论的否定/替代采用 F09 的明确范围确认，不靠确认先后隐式执行。

### F08-R05：任务字段与来源范围变化

审核中目标实质变化时核对相关记录范围；普通重命名不废弃整份事实记录。
任务状态变化在预览显示当前值，记录确认不恢复旧状态；完成/取消不自动停止其他对话。
项目成果源任务重开或源正式材料变化时，显示原截止与新范围、哪些来源变化，再按 F13/F14 核对。
原成果草稿保留，不能无提示当作新的当前完成成果确认；不补写源任务未确认工作。

### F08-R06：同一更新只生效一次

详情、对话侧栏、集中列表和不同窗口引用同一活动更新/确认身份。
正式提交时同时检查是否已处理与当前基线；同一更新连点或超时重试只得到同一真实结果。
已处理入口不重复生成版本，不再次推进处理位置，不重复减少待确认数量。
不同更新竞争同一汇总时保留独立草稿，要求后提交者看到并核对最新汇总。
不能用整项目长时间锁来替代记录级独立活动与确认时核对。

### F08-R07：持久化和可恢复性

成功前不展示整体成功，不发布半份正式结果；失败保留候选、编辑和用户选择。
保存结束后的正式读取从一致结果取值，不能让另一窗口读到记录新、概况旧的部分状态。
中断或超时结果未知时先核对已提交结果，不盲目重发整理或正式确认。
历史失败草稿不永久锁住入口；恢复同一对象，不重建重复任务、对话或确认项。

## 5. 异常、取消与恢复

- A 保存失败：A 正式内容不变，B 不读取失败候选；A 草稿与 B 草稿均保留。
- B 刷新建议失败：保留记录人工结果和待核对状态，允许重试或手动核对最新概况。
- AI 不可用：仍可手动核对竞争变化，不要求模型可用才处理本地正式更新。
- 用户取消 B：不撤销 A 成果，不改变 B 正式记录；若放弃 B 更新则 F06 保留待整理提示。
- 连点或双窗口同时确认同一项：显示一个实际结果，另一处已处理，不重复版本。
- 两个不同更新几乎同时提交：只让满足所核对基线的结果生效；另一项保留编辑并核对最新汇总。
- 基线变化来自普通重命名：显示当前名称，不整稿失效；目标实质变化核对相关工作范围。
- 重启、草稿恢复失败或结果未知：不清数据、不猜已确认，恢复已保存候选并明确核对对象。
- 项目范围不确定或来源不可读：不能写入猜测目标；说明缺失来源，保留原稿和正式数据。
- OQ-01 所述运行中提前整理仍未定义，不把并发确认机制扩大为待整理队列。

## 7. 实施边界与交接

可选择差异呈现和核对入口形式；基线保护、人工编辑保留、单次生效和独立草稿范围不可调整。
技术方案可以选择事务、操作记录或其他可靠实现，但必须用用户可见的成对一致结果验证。
不替用户自动裁定分歧，不以默认运行状态自动完成、取消或停止对话。
F13 引入项目成果时复用本核对契约，补充任务完成范围，不另建与任务记录矛盾的竞争规则。
实现前创建 implementation.md，验收时创建 verification.md；进度与验收状态见 [交付状态](../../../delivery/status.md)，不在本 PRD 内维护。
本功能可调整确认协作、版本检查、冲突预览和恢复；不得修改原始聊天内容。
