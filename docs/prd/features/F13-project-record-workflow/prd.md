## 1. 目标与范围

用户明确完成任务后，将已确认的阶段成果沉淀为一份当前项目记录，并同步精简项目总览。
完成任务、生成候选和确认保存是三个动作；任何生成动作都不替用户改变任务状态。
本功能包含缺失检查、系统整理对话、来源受控读取、成对审核和一次保存。
不包含自动判断完成、自动验证成果、修改代码或继承工作对话全量上下文。
同任务重开与再次更新由 F14 管理；本功能从首次生成即保持每任务一份当前成果的标识合同。
手动总览初始化由 F03 提供，不要求先产生已完成任务。

## 3. 用户流程与界面职责

1. 已完成任务详情显示“生成项目记录”，已有成果显示“更新项目记录”。
2. 点击后列出仍运行对话、未形成记录工作、缺少概况和本次正式来源。
3. 用户选择补齐材料，或明确按现有正式内容继续；不强制全部对话停止/有记录。
4. 系统自动创建本次项目整理对话并发送要求，无需另选执行对话或手填指令。
5. 界面展示真实进度、查看整理对话、取消与重试；关闭界面不执行额外工作。
6. Agent 先产出本任务项目记录，再提出保留其他贡献的总览更新。
7. 同屏预览两侧变化、来源与截止；用户可编辑并核对总览。
8. 核对完成后一次确认，成功才更新成果列表、总览、版本和待确认状态。

成果列表显示当前记录、任务来源、截止与待更新提示，历史按需展开。
整理过程可查，但过程对话不能冒充实际完成工作的证据。
来源不齐也可生成，只能明确说明已有内容与缺失，不能推断未记录工作已完成。

## 4. 功能规则

### F13-R01：完成与入口

正常生成与确认应对应仍存在、已完成且未归档的来源任务；归档先恢复，已取消/进行中不冒充完成成果。
标记完成不自动生成，不强制停止其他对话，不强制先整理所有工作。
已有活动草稿再次点击打开同次进度/草稿，不另建确认项。
生成期间任务重开保留草稿，提示当前完成范围已变化，不能无提示确认成当前完成成果；F14 接入后按其规则继续核对。
生成期间归档保留草稿，恢复来源任务后再正常确认。来源删除或不可用时明确影响，不能无提示发布新的当前完成成果、用同名任务替代或重建来源。
上述正常生成限制不禁止手动纠正已保存成果；即使来源不可用，F14/F10 的纠正路径仍保留已确认内容、来源标识和明确截止范围。

### F13-R02：缺失与截止

检查运行中对话、未记录工作、当前概况和正式记录可用性。
展示当前正式来源与明确截止，让用户补齐或按现有内容继续。
没有已记录细节时可说明“用户已标记完成，成果细节待补”。
任务目标、计划、候选方案和未经执行验证不能被推断为完成成果。

### F13-R03：系统整理对话

本次整理对话归当前项目并标明成果来源任务，独立于工作对话。
不计工作对话列表/数量，不产生“工作未形成记录”提示，不允许改成其他任务工作对话。
每次新整理使用新系统对话；同次失败重试或更新建议保留同一对话和编辑。
同次重试先核对执行结果，只补失败步骤，不无条件重建对象或重复派发。

### F13-R04：整理来源

初始只含任务信息、正式概况、当前总览、已有本任务成果和必要来源索引。
相关正式任务记录按需读取；不继承最后工作对话全文、不加载全任务正文兜底。
记录来源为实际工作对话的正式任务记录及其版本，系统整理对话另标生成过程来源。
不默认读原始聊天、历史、其他任务草稿或跨项目材料。

### F13-R05：成果与总览职责

项目记录含目标与完成边界、主要成果、决策、产物与验证、影响/依赖、风险、确切来源和截止。
项目总览含目标范围、共享约定/有效决策、成果索引、跨任务依赖、风险和后续方向。
总览保持精简，不逐条粘贴成果正文/历史，不另设重复维护的共同约定事实源。
成果截止不作为改变看板状态的依据；总览不能自动改写仓库需求或事实文件。

### F13-R06：适用性与用户补充

引用来源结论时附有效修正与范围；被否定结论不写成当前项目共识。
旧方案验证不转用为新方案证据，待确认结论只能为未决问题/历史说明。
用户补充标用户来源，未经确认不成为正式事实；人工修正不能被静默覆盖。
已有成果包含失效引用时，即使未重生成，读取也携带修正，不能继续作为事实。

### F13-R07：核对与成对确认

记录和总览同屏预览；记录实质编辑后总览重新标待核对，不随输入自动调用 AI。
允许请求更新建议或手动核对，保留两侧用户编辑与其他任务贡献。
未决结论可以保存为问题；总览一致性待核对阻止正式保存，两者不可混淆。
不同任务草稿独立；别人先更新总览仅核对受影响汇总，不废弃本任务草稿。
一次确认一致生效，仅实质变化对象生成版本，无变化不制造版本。

## 5. 异常、取消与恢复

| 场景 | 用户结果与恢复 |
| --- | --- |
| AI 整理失败 | 保留同次对话、草稿和编辑，可重试或手动维护 |
| 连点/多个入口 | 同次整理一个结果，打开已有草稿，不重复对话/确认项 |
| 保存失败 | 两侧均不正式生效，候选保留；成功后只一个结果 |
| 取消/放弃 | 不完成/取消任务，不删正式成果，不影响其他任务草稿 |
| 来源/总览变化 | 保留编辑，核对最新来源和总览；缺失范围明确 |
| 生成期间归档/删除来源 | 归档保留稿，恢复后再正常确认；删除/不可用明确来源影响，不自动发布或重建。已有保存成果仍可手动纠正 |
| AI 不可用 | 本地查看/编辑与手动核对可用，生成说明原因 |
| 重启/结果未知 | 恢复正式内容及已存草稿，核对未知过程，不自动重发 |

## 7. 实施边界与交接

允许调整缺失清单与预览布局；不能让用户手动创建/选择整理对话成为必经步骤。
成果、总览与工作记录分别存在，不能合并成一份改名后的材料。
交付成果固定标识、来源版本与截止合同，供 F14 的生命周期判断使用。
实现前创建 implementation.md；验收时创建 verification.md；进度不在本 PRD 内维护。
