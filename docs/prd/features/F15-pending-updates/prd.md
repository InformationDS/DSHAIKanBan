## 1. 目标与范围

用户在项目内集中找到真正需要审核的候选，并能分辨“有草稿”和“需要采取行动”。
成对记录与汇总算一个确认项，多入口处理使用同一候选身份。
本功能包含分类、时间排序、来源跳转、核对提示、数量同步和一次事件提醒。
不包含跨性质全部确认、批量放弃、权限审批处理或问题自动回答。
已完成未生成成果、成果待更新、工作有新内容属于行动提示，不凭空生成候选。
确认保存与编辑核对复用前置功能，本功能不建立第二套保存流程。

## 3. 用户流程与界面职责

1. 看板项目栏显示当前项目待确认数量，点击进入集中列表。
2. 列表按任务记录更新、项目记录更新、手动概况/总览草稿分类。
3. 每项显示任务、来源对话或成果任务、生成时间、变化摘要和需核对原因。
4. 用户打开项后进入其原有成对预览，继续编辑/核对后一次保存。
5. 成功后从可确认数量移除，各任务详情和列表显示相同已处理结果。
6. 保存失败则候选仍在，数量不减少，编辑与选择保留。
7. 行动提示引导去具体任务补齐/生成/更新，未开始就没有草稿。
8. 整理完成或失败等事件只提醒一次，用户可关闭非关键完成提醒。

空列表显示当前项目没有待确认项，不表述为所有任务已经完成。
整理中项可显示进度但不计可确认数量；需要核对的草稿单独标识。
任务卡片进展仍来自正式概况，不能因有候选就把草稿进展显示为正式。

## 4. 功能规则

### F15-R01：稳定计数单元

一组任务记录和概况候选只计一项，一组项目记录和总览候选也只计一项。
同组只一侧实质变化也保持同一审核项，不拆成两次确认。
不同对话/任务草稿独立列出，不能因另一项存在而禁用所有整理入口。
未确认候选即使需要核对仍属于待处理草稿，但明确不能直接保存。

### F15-R02：状态分类

已确认、已放弃和整理中不计可确认数量；已处理项必要时可查看结果。
手动草稿标“用户编辑”，不能称为 AI 建议。
汇总一致性待核对与内容中的待确认结论分别标识。
未决结论可作为问题保存；一致性待核对才阻止正式保存。

### F15-R03：行动提示

已完成但未生成项目记录提示“待生成项目记录”，不生成空候选。
成果来源变化提示“项目记录待更新”，不后台整理或自动增加数量。
工作有新内容只提示可形成任务记录，不自动执行，不阻止新建对话/完成任务。
来源任务已删除时不提供记录整理行动，不计该任务新内容或任务草稿提示。

### F15-R04：入口一致

详情、侧栏和集中列表引用同一更新标识及当前处理状态。
从任一入口保存成功后，其他入口核对并显示已处理，不二次保存。
保存失败、未知结果不提前移除；未知结果核对前不宣称已确认。
多窗口同时确认只有一个有效结果；竞争汇总走对应预览核对。

### F15-R05：列表信息与排序

默认按待确认时间排序，分类可查看，不按最后一次普通浏览重新排时间。
来源标识须足以区分同任务两条对话、不同任务同名成果。
缺失来源保持标识和说明，不指向同名替代对象。
只显示当前项目项，项目切换后的数量、通知入口和跳转不能串项目。

### F15-R06：通知事件

整理完成、失败或其他真实状态变化产生应用内一次提示。
静态待确认状态不能在重复打开页面或重启后无限提醒。
非关键完成提醒可关闭；失败/需核对提示仍在相关界面可见。
权限审批、待回答问题、记录确认分别命名，无跨性质“全部确认”。

### F15-R07：草稿与正式来源

卡片、概况、总览和背景默认读取仅使用正式内容，列表候选不隐式生效。
待确认数量不是未决结论数量，也不是已完成未生成成果的任务数量。
放弃候选不删正式记录、不取消任务、不影响其他候选。
无变化整理完成不生成候选；相关新内容处理位置由 F06 可靠推进。

## 5. 异常、取消与恢复

| 场景 | 用户结果与恢复 |
| --- | --- |
| 列表读取失败 | 展示读取失败/重试，不显示假空列表或把数量清零 |
| 保存失败 | 候选和数量保留，编辑/选择保留，回原预览重试 |
| 结果未知 | 标需核对，查询原更新结果，不重新创建候选 |
| 重复点击/多入口 | 同一预览/候选身份，已处理时显示实际结果 |
| 来源/汇总更新 | 原预览保留编辑，标受影响部分待核对 |
| 取消/放弃 | 取消返回保留草稿，明确放弃只移除该候选 |
| AI 不可用 | 列表与本地手动核对可用，AI 生成入口说明原因 |
| 重启 | 恢复已保存草稿状态和计数，不自动确认或重复提醒静态状态 |
