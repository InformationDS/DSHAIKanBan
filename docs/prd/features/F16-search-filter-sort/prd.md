## 1. 目标与范围

用户能在当前项目找到包含特定事实的任务，组合筛选并按合适顺序继续处理。
搜索当前正式信息，不让旧历史或失效结论无标识冒充当前事实。
包含标题/目标/概况/当前记录/原因搜索、筛选组合、匹配计数、归档纳入与排序。
跨项目统一搜索和独立列表视图为 P1，不在首版。
AI 按需检索由 F12 实现；用户看板搜索不直接授权 AI 读取结果。
项目对话列表的标题搜索由 F04 负责，不混用任务和对话搜索范围。

## 3. 用户流程与界面职责

1. 默认进入当前项目活动任务，搜索为空，按手动顺序显示。
2. 输入关键词，显示匹配卡片及来自哪个正式字段/记录的命中。
3. 选择任务状态与待处理筛选，列头显示匹配数/总数。
4. 选择包含归档时，归档结果有明确标记。
5. 切换最近更新排序，界面说明当前顺序模式。
6. 打开结果查看详情，返回保持查询、筛选、顺序与定位。
7. 清除搜索或筛选，恢复可见范围；切换项目使用其独立偏好。

无任务和无匹配结果分别表达：前者提供创建，后者提供清除筛选。
筛选条件可见且可清除，不能把隐含过滤伪装成任务丢失。
状态和归档标识有文字，键盘可操作搜索及筛选。

## 4. 功能规则

### F16-R01：当前搜索范围

仅当前项目，覆盖任务标题、目标说明、当前正式概况、每条对话当前正式记录与阻塞原因。
历史版本正文、未确认草稿、原始聊天不默认纳入。
项目成果和总览可在其所属查看界面读取，不擅自扩展本条指定任务搜索字段。
搜索结果定位任务及命中字段/来源，不把同名任务自动合并。

### F16-R02：失效或未决片段

当前正式记录中的旧方案仍可能命中关键词，命中不能只截出原句。
必须同时显示已被替代、已否定或待确认结论状态、适用范围与已确认修正。
有效片段不因同记录另一片段失效被一并隐藏。
当前适用和待确认结论不能用同一“待确认”标签混为草稿状态。
修正生效后即更新命中视图，不等正文重新生成，也不等项目成果重生成。

### F16-R03：归档范围

默认仅活动任务，可明确选择包含归档。
归档命中显示归档标记，打开可查看；开始新工作须按 F17 先恢复。
删除任务不留为可打开任务结果，已保存项目成果中的删除来源另行保留。
归档不是任务状态，不能用状态筛选代替归档开关。

### F16-R04：筛选集合与组合

支持任务状态、待确认、阻塞、等待用户处理、项目记录待生成/待更新筛选。
同类别多值任选其一；不同类别共同满足。
搜索与筛选共同约束结果，显示已选条件及清除入口。
待生成项目成果不是草稿，不能混入待确认数量。
卡片提示来源于真实状态，不因搜索建立新的待处理事实。

### F16-R05：匹配计数与空状态

每列显示匹配/总数量，两者使用相同项目与归档范围，明确总数不受关键词限制。
一项任务多个字段命中仍只计一项任务。
有任务但被条件排除显示无筛选结果，提供清除，不暗示数据为空或被删除。
加载或查询失败不可显示可靠的零结果，提示失败与重试。

### F16-R06：排序与偏好

默认手动排序，支持最近实质更新排序，页面打开不算更新时间。
自动排序模式不承诺拖动保存手动顺序；可以禁用顺序拖动或提示切回手动。
状态改变拖拽与列内排序拖拽分别表达，不因自动排序失去状态菜单操作。
搜索、筛选、排序、详情定位按项目分别保留，不写成全局偏好。
保存偏好失败应反馈，不影响已保存任务内容。

### F16-R07：搜索与 AI 分离

查看命中、打开来源或历史不自动向 AI 投递全文。
搜索输入不变成长期要求，不修改任务状态、正文或结论适用性。
若用户另行发出追溯/查证请求，材料读取按 F11/F12/F20 的实际范围执行。
不因索引或搜索方便预加载全部历史及工作目录文件。

## 5. 异常、取消与恢复

| 场景 | 用户可见结果与恢复 |
| --- | --- |
| 查询失败 | 保留输入和已选条件，提示重试，不报确定零命中 |
| 读取某来源失败 | 标出受影响范围，不删任务，不把草稿当正式补全 |
| 快速输入/重复查询 | 只显示当前查询结果，不把较早返回结果覆盖新条件 |
| 取消或清除条件 | 恢复相应范围，不删除任务或改状态 |
| 搜索期间正式来源/修正变化 | 使用当前正式结果或标记更新，不继续展示无标识失效事实 |
| 偏好保存失败 | 当前操作可见，提示未保存，允许重试，不误改其他项目 |
| AI 不可用 | 全部本地搜索、筛选、排序正常可用 |
| 重启 | 恢复已保存项目偏好，查询错误不清数据；不存在 AI 草稿生成 |

## 7. 实施边界与交接

允许选择搜索匹配方式及排序相同时间的稳定次序，须在 implementation.md 说明。
不可改为全量历史默认搜索，不能省略修正信息或用草稿当事实。
实现范围为看板查询、条件组合、结果标注及项目偏好；不实现跨项目搜索。
实现前创建 implementation.md，列出字段范围、计数口径和最新适用性更新机制。
验收时创建 verification.md，记录对照数据、筛选组合与实际 AI 无投递证据。
全局状态不在本 PRD 内维护。
