# 未决事项与首版边界

本页记录原文明确未定义或需要实施前确定的边界，以及明确排除首版的事项。未决只阻止依赖该决定的部分，其他已确定需求继续开发；排除首版的事项保留编号与追溯，不自动升级为 P0 待开发。

## 用词口径

- **未决 / 待定**：用于业务行为尚未完整定义、需在对应入口实现前明确的事项（OQ-01）。它只阻止依赖该决定的分支，不表示整个功能延后，也不阻止其余已确定路径开发。
- **排除首版**：用于明确不进入首版范围、只保留编号追溯的事项（OQ-02、FR-27）。它不是待开发项，重新纳入须先补定义与验收。
- 「暂缓」不再作为本仓库的状态用词；roadmap、overview、公共规则与功能 PRD 引用本页边界时统一使用上述两个词。

## OQ-01 运行中点击形成任务记录的最小反馈

- 来源：基线 FR-14—15、17.5 第 2 项。
- 状态：业务尚未完整定义（未决/待定），需要在 F06 的运行中整理入口实现前明确。
- 已确定：正常路径是相关对话工作结束后点击整理；默认整理期间无新增工作。这是使用假设，不是全项目工作必须同时结束的强制关卡。
- 待定：工作正在运行时点击如何给出最小可理解反馈。停止、失败、等待回答/审批及重启后队列行为尚未定义。
- 实施限制：不要自行实现等待队列、自动触发整理、调度或强制全项目串行；也不要擅自把禁用按钮/自动停止当已确定产品方案。正常已结束工作路径可先实现，运行中分支单独保留待定标识，不能宣称完整入口已验收。
- 需得到的决定：明确入口可见/可用行为、提示文字和是否留下待处理意图；涉及范围若扩大，另行更新需求及验收。
- 完整首版判断：处理这一局部边界后方能完成对应入口验收；不凭空增加原 106 场景中的队列验收。

## OQ-02 项目备份与恢复排除首版

- 来源：FR-27、14.3、17.4 第 5 项。
- 状态：排除首版，保留编号追溯，不是上线依赖。
- 排除：导出备份、导入、独立项目恢复、覆盖恢复、自动备份。
- 保留：日常保存、已保存草稿中断恢复、四类内容历史恢复、当前背景复制均仍为 P0。
- 重新纳入时：先定义项目标识、来源、归属、覆盖影响及失败保护，不直接复用旧的假定备份流程。

## OQ-03 技术架构与宿主能力状态

- 来源：基线第 3.3 章及用户要求以此目录作为开发项目；这是工程准备未决，不是新增产品功能。
- 状态：工程未决/待定：尚未选框架、存储、模型调用实现；无已有宿主能力证据；S0 尚未实施。
- 处理入口：架构与宿主能力在实施阶段确定，技术选择记入[技术决策记录](../engineering/decisions/README.md)，实施与验证进展登记到[交付状态](../delivery/status.md)；本仓库只保留需求与治理约定。
- 限制：不要默认 DSH 的项目/聊天/模型入口已存在，不借本次拆分定义所有终端/文件权限功能。仅确定满足 AIKanBan 必需边界的最小工程方案。

## 已确定事项不重新变成开放问题

结论片段适用性、固定唯一归属、整条对话提炼且无消息选择、同项目按问题自主读取、编辑后核对完整操作、无需更新清提示、删除来源限制、两个核对状态的区分均已确定。按公共规则及小 PRD 实施，不为了拆小文档删去这些要求。
