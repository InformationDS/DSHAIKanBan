# 未决事项与首版边界

本页记录原文明确未定义或需要实施前确定的边界，以及明确排除首版的事项。OQ-01 已于 2026-10-19 确定，当前仅 OQ-03 为工程未决。未决只阻止依赖该决定的部分，其他已确定需求继续开发；排除首版的事项保留编号与追溯，不自动升级为 P0 待开发。

## 用词口径

- **未决 / 待定**：用于业务行为尚未完整定义、需在对应入口实现前明确的事项。OQ-01 已于 2026-10-19 确定，当前仅 OQ-03 为工程未决。它只阻止依赖该决定的分支，不表示整个功能延后，也不阻止其余已确定路径开发。
- **排除首版**：用于明确不进入首版范围、只保留编号追溯的事项（OQ-02、FR-27）。它不是待开发项，重新纳入须先补定义与验收。
- 「暂缓」不再作为本仓库的状态用词；roadmap、overview、公共规则与功能 PRD 引用本页边界时统一使用上述两个词。

## OQ-01 运行中点击形成任务记录的最小反馈（已确定）

- 来源：基线 FR-14—15、17.5 第 2 项。
- 状态：已确定。2026-10-19 用户决定：采用最小提示、不阻断方案。
- 已确定：正常路径是相关对话工作结束后点击整理；默认整理期间无新增工作。这是使用假设，不是全项目工作必须同时结束的强制关卡。
- 决定（最小提示、不阻断）：运行中点击“形成任务记录”时入口保持可用，不灰化禁用、不阻断、不排队、不自动停止对话、不自动触发整理；系统照常在该工作源对话发送可见整理要求，整理范围只限截至点击时已结束的内容，正在进行的这一轮不计入；界面显示“本对话仍在运行：本次整理只覆盖已结束的内容。本轮完成后可再次整理，以更新同一条记录。”；不留阻塞式待处理意图，不在对话结束后自动补发整理要求，重启后也不自动重发；失败/未知沿用 REC-03，连点/重试按 REC-02。产品规则与验收落点为 F06-R09 与 AT-129。
- 实施限制：按 F06-R09 执行；不得实现等待队列、自动触发整理、调度或强制全项目串行；不得把禁用按钮/自动停止当作实现方式。原「运行中分支单独保留待定标识」已随本决定取消，F06 入口按 AT-129 验收。
- 已答要点：入口可见/可用行为=保持可用（不灰化、不阻断、不排队、不自动停止）；提示文字=“本对话仍在运行：本次整理只覆盖已结束的内容。本轮完成后可再次整理，以更新同一条记录。”；是否留下待处理意图=不留。
- 完整首版判断：本边界已确定，按 F06-R09 与 AT-129 完成对应入口验收；不凭空增加原 106 场景中的队列验收。

## OQ-02 项目备份与恢复排除首版

- 来源：FR-27、14.3、17.4 第 5 项。
- 状态：排除首版，保留编号追溯，不是上线依赖。
- 排除：导出备份、导入、独立项目恢复、覆盖恢复、自动备份。
- 保留：日常保存、已保存草稿中断恢复、四类内容历史恢复、当前背景复制均仍为 P0。
- 重新纳入时：先定义项目标识、来源、归属、覆盖影响及失败保护，不直接复用旧的假定备份流程。

- 来源：基线第 3.3 章及用户要求以此目录作为开发项目；这是工程准备未决，不是新增产品功能。
- 状态：工程未决/待定：尚未选框架、存储、模型调用实现；无已有宿主能力证据；S0 尚未实施。
- 处理入口：架构与宿主能力在实施阶段确定，技术选择记入[技术决策记录](../engineering/decisions/README.md)，实施与验证进展登记到[交付状态](../delivery/status.md)；本仓库只保留需求与治理约定。
