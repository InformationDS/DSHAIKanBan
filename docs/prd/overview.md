## 产品与用户

AIKanBan 面向以 AI 对话持续推进本地项目的个人开发者及独立项目负责人，是从零开发的 Deepseek Harness 桌面版中的项目看板与跨对话交接功能。它用任务组织多条对话，让不同阶段的真实成果经用户确认后成为下一轮工作的可信背景。

项目、对话、运行、模型设置、文件权限和终端能力不能仅因 PRD 提到就当已实现；本产品所需宿主能力在实施阶段另行确定，不在此假定。不据此扩大为整套未定义的桌面 Agent 产品。

## 主要问题与能力

| 问题 | 对应能力 |
| --- | --- |
| 多条对话成果分散 | 每对话独立任务记录 |
| 换对话重复说明 | 当前任务概况和项目总览作为默认背景 |
| 后一条覆盖其他贡献 | 保留多来源及人工修正、竞争时核对 |
| AI 摘要有误 | 可编辑草稿与一次成对确认 |
| 阶段结束混同任务完成 | 对话运行与用户任务状态分开 |
| 完成成果未沉淀 | 每成果任务一个当前项目记录及精简总览 |
| 历史导致上下文膨胀 | 当前内容默认读，历史明确按需 |
| 中断丢输入或重复执行 | 保存草稿、核对实际结果再重试 |

## 核心闭环

创建任务 → 任务内新建对话 → 准备背景并等待用户发送 → 工作结束后形成记录与概况候选 → 一次确认一致生效 → 下一对话用当前正式背景接续 → 用户标记完成 → 系统整理对话生成项目记录与总览候选 → 一次确认沉淀成果。

同时支持：项目内未关联对话先工作 → 明确选择/创建任务并关联 → 从整条对话提炼相关结论 → 审核确认后进入上述闭环。不选择消息片段、不重建聊天，关联本身不确认旧成果或执行。

这是常用路径而非强制关卡。无记录可工作，未结束/未记录可另开对话，完成不强制全记录，不自动停止；未关联对话可一直独立工作。整理期间没有新增工作是使用假设，须通过试用验证，不宣称系统强制保证。

## 信息架构

- 项目看板：任务创建、状态、卡片、搜索筛选及详情定位。
- 任务详情：当前概况、多条工作对话、当前记录、待确认、成果入口；更多操作包含归档删除。
- 项目对话列表：独立新建、打开、按归属筛选与标题搜索。
- 对话任务侧栏：归属、正式概况、实际背景版本、整理与返回；删除来源按 OBJ-09 显示。
- 项目总览与成果：默认精简总览，下方各成果任务的当前条目、来源和待更新提示。
- 集中待确认：一条记录及汇总为一个项，与成果待生成等行动提示区分。

窄窗口详情可全页呈现，返回保留定位筛选。全文、来源、版本按需展开；主要动作不被多层管理页面或重复确认遮住。

## 首版范围

20 个 P0 小 PRD 共同覆盖原 A—F 交付包及 106 个 AT 场景。阶段内可试用，只有全部 P0 与联合验收通过才是完整首版。任务记录/项目记录与对应汇总的成对确认、人工修正、背景实际范围、保存失败保护从所属功能第一次实现即生效。

P1 候选包括多行批量建任务、列表视图、跨项目搜索、批量归档/放弃、标签优先级、轻量提醒、方案比较、停止全部。P2/范围外包括多人协作、云同步、远程移动访问、排期工时、甘特图、复杂自定义字段流程、外部双向同步、模糊目标自动拆项目、跨平台对话接管、跨项目长期共享。

备份导出导入及自动备份暂不考虑；运行中整理反馈未完整定义，见[未决事项](open-questions.md)。文件并行修改协调由 Agent/桌面能力处理，看板不增加文件锁、调度、差异合并界面；记录如实表达已报告冲突和未验证结果。

自动确认记录、AI 结束自动完成任务、自动裁定冲突违背核心原则，不作为未来候选。

## 成功判断与指标

主指标是多对话任务闭环完成率：多个对话推进、独立记录和可信概况、用户决定完成、最后确认项目成果与总览更新。尚无实际基线，以下是试用目标而非已达成结果。

- 至少 3 个真实任务，每项至少 2 条独立对话，覆盖人工修正、并行核对、缺记录完成、重开更新、保存失败、中断恢复、先对话后关联。
- 跨对话接力观察至少 10 次，建议至少 9 次不用复制旧聊天即可正确继续；小样本只用于发现问题。
- 至少 5 位目标用户试用，至少 4 位能区分阶段记录、任务完成与项目成果；观察成对审核负担与编辑核对成本。
- 标题即可创建；任务内一次新建；任务/项目成果均一次生成、一次正常预览确认；进展不重复填写。
- 默认历史正文量为 0；仅增加历史数量但当前正文不变，默认背景不增长。实际新增正文和主动检索仍可能增加上下文，不承诺零成本。

未确认事实泄漏、历史默认灌入、误项目背景、静默覆盖、半生效、重复成果/版本、未经要求自主执行、数据丢失、删除波及聊天/代码目标均为 0。任何出现都是首版阻断项，见[验收映射](mapping/acceptance.csv)。

## 呈现与规则边界

布局、侧栏/全页、排序呈现、差异排版、索引及历史折叠样式可由设计决定；不能隐藏失败/删除/冲突、增加普通确认次数、改变历史读取范围或强制关闭记录对话。业务规则变更须明确记录，不能作为视觉调整实施。
