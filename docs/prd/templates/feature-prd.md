# Fxx：功能名称

| 属性 | 内容 |
| --- | --- |
| 功能编号 | Fxx，创建后保持稳定 |
| 优先级 / 阶段 | P0 / Sx，阶段不改变优先级 |
| 原始来源 | 基线的 FR 条款、章节与 UX 编号 |
| 前置依赖 | 必须已完成的功能及需要的宿主能力 |
| 验收来源 | AT 编号，跨功能场景注明协同功能 |

## 1. 目标与范围

说明主要用户完成的一个行为、成功结果、本次包含与不包含内容。不得虚构调研、已实现能力或已通过的验收。

## 2. 必读规则与依赖

链接必要公共规则，并精确列出规则编号；不要默认要求阅读全部原始 PRD。说明直接依赖提供什么、未来功能加入时需集成什么。公共规则从首次实现即有效。

## 3. 用户流程与界面职责

描述入口、主要操作、结果、返回路径、空状态及实际数据来源；页面布局可调整，业务行为不能自行调整。

## 4. 功能规则

使用 Fxx-R01 等稳定编号；写清对象、触发、状态变化、来源、保存和读取边界。明确需要用户确认的具体动作。正文必须足以实现本功能，不用“按原文执行”代替规则。

## 5. 异常、取消与恢复

按场景给出用户可见结果、保留内容与重试方式；至少核对失败、连点、取消、来源变化、AI 不可用、重启，不适用时说明原因。

## 6. 验收条件

使用具体前置条件、操作、预期结果。引用 AT 的同时给出可执行步骤与判断，标明本功能验收或跨功能联合验收。所有场景初始为待执行，不代表已通过。

## 7. 实施边界与交接

说明可调整呈现、禁止改变的语义、未决事项、允许改动范围。实现前创建 implementation.md，验收时创建 verification.md；进度与验收状态单独维护，勿在多处维护不同状态。
