# 单功能开发任务模板

请实现 [Fxx 功能名称]，需求入口为 [features/Fxx-slug/prd.md]。

1. 先读取项目 README、该 PRD 的最小必读规则与直接依赖合同，并核对该依赖的实际实现/验证证据；不默认其已存在。
2. 在该功能目录创建 implementation.md，写本次完整用户行为、直接依赖、允许改动范围、实现顺序、具体校验和尚未明确的局部边界。
3. 实现一个可运行、可保存、可验收的用户行为，覆盖 PRD 明确错误/取消/重试规则。不得扩大 P1/P2、自行改绑、自动执行/确认、按最后写入覆盖、加入全历史。
4. 适用规则已有实现应复用；缺口明确补齐，不把对话/模型/存储当现成。OQ-01 仅影响尚未决定的运行中整理分支，其余已确定行为继续推进。
5. 按 PRD 验收和关联 AT 检查，创建 verification.md，写实际输入、操作、结果、证据、通过/失败/待执行及局限。跨功能条件未就绪时明确待联合验收，不伪报通过。
6. 更新实现与验证状态；必要架构决定写 ADR；文档变更运行 `docs/tools/check_docs.py`。最后给出改动、实际验证、遗留与下一功能入口。

实现记录建议结构：范围和依赖 / 实现计划 / 实际改动 / 技术决定链接 / 遗留。

验证记录建议结构：环境和版本 / 本功能用例 / 跨功能 AT / 证据 / 失败及未执行项 / 结论。不要预填虚构通过结果。
