# 单功能开发任务模板

请实现 [Fxx 功能名称]，需求入口为 [features/Fxx-slug/prd.md]。

1. 先读取项目 README、该 PRD 的最小必读规则与直接依赖合同，并核对该依赖的实际实现/验证证据；不默认其已存在。
2. 在该功能目录维护 implementation.md，写本次完整用户行为、直接依赖、允许改动范围、实现顺序、具体校验和尚未明确的局部边界。**M6 规则**：`implementation.md` 在**首次实现**时创建；后续扩展/修正时**追加章节并注明日期与提交号**，不得覆盖或删除既有记录。若该文件是「回收代码的现状盘点」这类非实现记录，必须在标题与首段**标明性质**（例如「现状盘点，不是实现记录」），不得冒充实现进度。**例外（S5 分工）**：跨功能接线（如切片 A）的实现记录写 `docs/engineering/s1-wiring-implementation.md`（见[验收执行规则](../../engineering/acceptance-execution.md)与 [s1-wiring](../../engineering/s1-wiring.md) §7.4），不写进功能目录；功能实现仍写各自 `implementation.md`。
3. 实现一个可运行、可保存、可验收的用户行为，覆盖 PRD 明确错误/取消/重试规则。不得扩大 P1/P2、自行改绑、自动执行/确认、按最后写入覆盖、加入全历史。
4. 适用规则已有实现应复用；缺口明确补齐，不把对话/模型/存储当现成。OQ-01 仅在运行中整理分支受限，其余已确定行为按 F06-R09 继续推进。
5. 按 PRD 验收和关联 AT 执行验收，**用 [verification 模板](verification.md) 创建该功能目录的 `verification.md`**（必填提交号、环境、AT 编号、证据档位、前置条件、步骤、预期、实际结果、证据、结论、局限）；AT 状态与证据口径按[验收执行规则](../../engineering/acceptance-execution.md)执行。跨功能未就绪时在「归属」列标注 `待联合验收`（归属标记，不是结论词），结论写 `待执行`/`部分执行`，不得伪报通过类结论；未执行一律「待执行」。
6. 更新实现与验证状态，只登记到[交付状态](../../delivery/status.md)，不在 PRD 内另写进度；必要架构决定写入 [ADR 目录](../../engineering/decisions/README.md)，按 `ADR-001-主题.md` 记录并遵守状态词表（`提议`/`已定`/`采用`）；文档变更运行 `docs/tools/check_docs.py`。最后给出改动、实际验证、遗留与下一功能入口。

实现记录建议结构：范围和依赖 / 实现计划 / 实际改动 / 技术决定链接 / 遗留（后续扩展追加「日期 + 提交号」小节，不覆盖旧内容）。

验证记录以 [verification 模板](verification.md) 为准，不要另起格式；不要预填虚构结果。
